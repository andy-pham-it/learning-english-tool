### Giai đoạn 2: Đề xuất giải pháp cơ bản (Brute Force Approach)
Luôn bắt đầu bằng giải pháp đơn giản nhất để chứng minh bạn hiểu bài toán, sau đó mới tối ưu.

**6. Đề xuất Brute Force:** "The most naive approach that comes to mind is a brute force solution where we compare every element with each other."
*(Cách tiếp cận ngây ngô nhất nảy ra trong đầu tôi là giải pháp brute force, nơi chúng ta so sánh mọi phần tử với nhau.)*
```javascript
// A nested loop example (O(n^2))
for (let i = 0; i < nums.length; i++) {
    for (let j = i + 1; j < nums.length; j++) { ... }
}
```
**7. Đánh giá Brute Force:** "While this approach works, it gives us a time complexity of O(N squared), which is not optimal for large datasets."
*(Mặc dù cách tiếp cận này hoạt động, nó cho chúng ta độ phức tạp thời gian là O(N bình phương), điều này không tối ưu cho các tập dữ liệu lớn.)*
**8. Báo hiệu việc chuyển hướng tối ưu:** "Let's see if we can optimize this to an O(N) solution by trading some space for time."
*(Hãy xem liệu chúng ta có thể tối ưu hóa điều này thành giải pháp O(N) bằng cách đánh đổi một chút không gian lấy thời gian hay không.)*

### Giai đoạn 3: Trình bày thuật toán tối ưu (Optimized Approach)
Nêu tên pattern/thuật toán bạn định dùng.

**9. Dùng Hash Map (Dictionary):** "I'm thinking of using a Hash Map to store the frequencies of the elements so we get O(1) lookups."
*(Tôi đang nghĩ đến việc sử dụng Hash Map để lưu tần suất của các phần tử nhằm có được thời gian tra cứu O(1).)*
```javascript
const map = new Map();
if (map.has(target)) return map.get(target);
```
**10. Dùng Hai con trỏ (Two Pointers):** "Since the array is already sorted, we can utilize the two-pointer technique to solve this in a single pass."
*(Vì mảng đã được sắp xếp, chúng ta có thể tận dụng kỹ thuật hai con trỏ để giải quyết vấn đề này trong một lần duyệt.)*
```javascript
let left = 0;
let right = arr.length - 1;
while (left < right) { /* move pointers */ }
```
**11. Dùng Cửa sổ trượt (Sliding Window):** "This looks like a classic sliding window problem because we need to find a contiguous subarray."
*(Đây có vẻ là một bài toán cửa sổ trượt kinh điển vì chúng ta cần tìm một mảng con liên tiếp.)*
```javascript
let windowStart = 0;
for (let windowEnd = 0; windowEnd < arr.length; windowEnd++) { ... }
```
**12. Dùng Đệ quy / DFS:** "I will use Depth-First Search recursively to traverse down to the leaf nodes."
*(Tôi sẽ sử dụng Tìm kiếm theo chiều sâu đệ quy để duyệt xuống các node lá.)*
```javascript
const dfs = (node) => {
    if (!node) return;
    dfs(node.left);
    dfs(node.right);
};
```
**13. Quy hoạch động (Dynamic Programming):** "Because there are overlapping subproblems, we can use dynamic programming with memoization to avoid redundant calculations."
*(Bởi vì có những bài toán con chồng chéo lên nhau, chúng ta có thể sử dụng quy hoạch động với kỹ thuật memoization để tránh các tính toán thừa.)*
```javascript
const memo = {};
if (n in memo) return memo[n];
```

**16. Xử lý logic bên trong vòng lặp:** "At each iteration, we'll calculate the current sum. If it exceeds the target, we shrink the window from the left."
*(Tại mỗi vòng lặp, chúng ta sẽ tính tổng hiện tại. Nếu nó vượt quá mục tiêu, chúng ta thu hẹp cửa sổ từ bên trái.)*

### Giai đoạn 6: Phân tích độ phức tạp (Complexity Analysis)
Chốt lại vấn đề bằng một bản báo cáo ngắn gọn về Big O.

**22. Độ phức tạp thời gian (Time Complexity):** "The overall time complexity is O(N) because we iterate through the input array strictly once."
*(Độ phức tạp thời gian tổng thể là O(N) vì chúng ta duyệt qua mảng đầu vào đúng một lần.)*
**23. Độ phức tạp Logarit:** "Since we are halving the search space at each step, the time complexity drops to O(log N)."
*(Vì chúng ta đang chia đôi không gian tìm kiếm ở mỗi bước, độ phức tạp thời gian giảm xuống còn O(log N).)*
**24. Độ phức tạp không gian (Space Complexity):** "The space complexity is O(N) in the worst-case scenario due to the extra memory allocated for the Hash Map."
*(Độ phức tạp không gian là O(N) trong trường hợp xấu nhất do bộ nhớ bổ sung được cấp phát cho Hash Map.)*
**25. Không gian hằng số (In-place):** "Because we are sorting the array in-place and using only a few variables, the auxiliary space complexity is O(1)."
*(Bởi vì chúng ta sắp xếp mảng tại chỗ và chỉ sử dụng một vài biến, độ phức tạp không gian phụ trợ là O(1).)*
